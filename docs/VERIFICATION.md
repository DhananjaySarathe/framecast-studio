## Screen Recording permission (packaged app)

For a while macOS kept asking for Screen Recording even though Framecast was switched on in System Settings.
Cause (from the `tccd` log): the permission entries had been stored against earlier builds' code hashes, and adding
the app again with "+" reused that stale record, so the current build never matched. Fix: `tccutil reset All
app.framecast.studio`, then allow camera, microphone and Screen Recording again when Framecast asks. The build is
signed with a stable local identity (`scripts/make_signing_identity.sh`), so later rebuilds keep the grants; the
self-signed certificate was not the cause.

## Privacy incidents during the build (all local, all fixed)

- While the captions test was being written (2026-11-04), a second copy of the test app (`build/test/Framecast.app`)
  was opened twice by macOS, not by the test: once between runs (found when the next run refused to start, around
  20:23) and once at 20:30:54 during a run. Both had no test environment, so they started as ordinary launches with
  the user's own settings and studio, which has cameras, the screen, a microphone and desktop sound, and they
  probably opened them; the first ran up to about two minutes, the second about two and a half. They didn't go live
  (no stream was started) and the studio file (`default.json`) wasn't changed; `Destinations.json` was rewritten with
  the same two destinations. Both were killed by PID. What opened them wasn't found (the system log isn't readable
  from the test; stopping a test copy didn't reproduce it in two tries); most likely opening Framecast from the Dock
  or Spotlight picked the test copy, which shares Framecast's bundle id. Fixed: `build/e2e/quick_build.sh` marks the
  test copy (`FramecastTestCopy` in its Info.plist), and a marked copy opened without `FRAMECAST_UI` now quits at once,
  before anything starts, and notes it in `$TMPDIR/framecast-test-copy-refused.log`; the captions test also kills any
  other test copy it sees and fails if one appeared. In the eight full runs and two kill probes since, none did.
  Then the test copy got its own bundle id and name (`app.framecast.studio.test`, "Framecast Test", set by
  `quick_build.sh` before signing and re-registered with LaunchServices), so macOS no longer counts it as Framecast;
  it also keeps its own settings domain. The marker stays as a safety net. A renamed copy has no file permissions
  of its own, so its stand-in media is read from `~/Library/Caches/framecast-e2e-media` (a copy of
  `build/e2e/media`), not from the repo under Desktop.

- mediamtx 1.21 enabled a MoQ listener on all interfaces (:8892/:8893) for about 15 seconds before it was stopped;
  the config now disables it and pins every address to 127.0.0.1.
- LiveKit's ICE/TCP listener bound `*:7881` for about 3 seconds in a test; ICE/TCP is now off and media uses UDP on
  127.0.0.1 only.
